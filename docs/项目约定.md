## 一、路线与目标

1. **原生移植**：自研 C/C++ 引擎 + SDL2，复用原版 PAK/SHP 资产。
   **明确排除** Winlator / Wine+Box64 兼容层路线（用户要求原生运行）。
2. **A → B 递进**：
   - **A 档（2~4 周）**：可运行原生原型 —— 加载原版素材、能开局、能打简化战斗、5 项需求全生效，demo 保真度。
   - **B 档（4~6 个月）**：逐系统对照原版校准，达成忠实还原。
3. **分阶段推进**：每阶段必须有**产出物**与**验收点**；重要方案**先成文确认再动手**。
4. **诚实优先**：可行性与工作量上限说清楚，不画饼；改造他人电脑上的文件/游戏**先备份、每步可回滚**。
5. **玩法优先，不逐像素复刻**（2026-09-15 用户确认）：老游戏有些东西过时了，
   复刻耗时的地方可以换更轻量的实现方式；但**核心玩法与 5 项需求不跑偏**。
   判断标准：影响"玩起来"的（布局错位、交互失效、数值规则）必须对齐；
   纯观感细节（动画、像素级装饰）可降级或后置到 M5。

## 三、分辨率与显示（用户两次强调）

1. 老游戏也要在安卓跑得舒服：**至少支持 2K（2560×1440）**，设计上限 4K；
   覆盖 **16:9 / 16:10 / 21:9（+ 手机 20:9）**。
2. **逻辑坐标与物理分辨率彻底解耦**：一切玩法/UI/命中判定用 **640×480 逻辑坐标**，
   代码里**不得出现**物理像素常量（2560/1440…）。换分辨率 = 换一个缩放系数。
3. 物理分辨率只出现在**视口变换层**（`engine/src/render.c` / `presenter.c`）。
4. **素材高清化 = 纯资源替换**：丢进 `Shape@2x/` 等目录即生效，**不改代码、不重编译、不重打包**。
5. **显示语言默认简体中文**（用户口径："不必完全复刻原版，优先支持简中显示"）：
   游戏数据是 Big5 繁体 → 设"显示语言层"，离线繁→简映射表（引擎侧只查表）。
   文本渲染统一经显示语言层，业务代码不直接接触 Big5 原文。
6. **内置可自由分发的开源中文字体**（SIL OFL-1.1）：霞鹜文楷（矢量，100% 覆盖，默认）+ 缝合像素 12px（简/繁子集，像素模式）+ 缺字回退链。
7. **手机长屏必须走 `EXTEND`**（横向扩展视野，UI 锚定 4:3 安全区）—— 不接受大黑边。
   关键数值：R 实测、4K 上限、20:9 两侧各 640px 黑边 → 故 M4 必须上 EXTEND。

> 详细规范见 `docs/分辨率与高清化架构.md`（四条铁律、坐标变换、滤镜、目标表、素材分级）。

### 三·补 渲染管线约定（2026-09-15 增补，改渲染前必读）

1. **"逻辑分辨率"不是常量**。素材分辨率高于 640×480 时（如战略地图 `Map.shp` 1024×768），
   该场景**应把逻辑画布切到素材原生分辨率**（`sango3_presenter_set_logical_size`），
   让 GPU 只做 2~3× 放大；塞进 640×480 画布再放大 = 先降采样再放大，**必然发糊**。
2. **宽高比三选一**（运行时可切，`sango3_presenter_set_aspect`）：
   | 模式 | 行为 | 适用 |
   |---|---|---|
   | `PILLARBOX` | 保比例留黑边 | 桌面兜底 |
   | `EXTEND` | 内容按长边撑满 + 余侧用**画布边缘条带镜像**填充 | **UI/菜单类场景**（不留黑边、不变形） |
   | `COVER` | 按短边撑满、溢出裁切（**顶对齐**） | **内容类场景**（战略地图） |
   > ⚠ COVER 不能垂直居中裁 —— 会把顶部信息条裁到屏幕外（实测）。
3. **滤镜随场景切**：像素素材 `NEAREST`（锐利）↔ 照片级大图 `BILINEAR`（平滑）。
4. **每帧必须清画布**（`s3_menu_render` 已内置）：场景不一定是全屏覆盖，
   不清屏会残留上一场景像素（实测踩坑）。
5. **视口滚动优于整图平移**：需要"看更大范围"时，画布尺寸 = 屏幕宽高比对应的素材区域，
   1:1 裁取渲染（清晰度不损），拖动只改视口原点并 clamp 在素材范围内。
6. **坐标语义两条**：INI 里**子窗口 `Range` 相对父窗口**（渲染与命中测试都要累计父偏移）；
   **城市按钮 `Range` 是矩形左上角**，中心 = `+w/2, +h/2`。

## 四、工程红线（数据与验证）

1. **C 与 Python 基准必须 100% 一致**：
   - 数据层改动后跑 `tools/verify_data_c.py`（**9024 项**）；
   - UI 布局改动后跑 `tools/verify_ui_c.py`（**11530 项**）；
   - **两者都必须绿**，否则视为回归。
2. **数据口径**：必须取 **Update.PAK 的 `Menu.ini`**（WINDOW 325 / ICON 303 / COLOR 36）；
   `define.ini` 只在 Sango3.PAK → **两个包都打开，Update 覆盖 Sango3**。
3. **不为"过验证"改写数据**：两侧用同一套**可逆转义**（`\t` `\n` `\r` `\\` `\xNN`），不丢信息。
4. **跨语言对照的列序必须在同一处双侧锁定**（C 侧 TSV 头注释写明列序，Python 侧同名校对）。
   教训：曾因漏读一列导致整体错位一格，报出 1480 项"假阳性"不一致。
5. **确定性产物必须可重建**：上游（PAK/INI/词条）变更后重跑生成脚本 + 双重验收。
6. **C 工具不要输出含中文的路径**（GBK 控制台会破坏路径字节）；路径拼接交给 Python 层。
7. 解析类工具要加 **sanity 计数**兜底（如 `range_wh_zero`），防"不报错但静默错"。

### 四·补 「不报错但静默错」防范清单（2026-09-16 归档自 `MEMORY.md`）

1. **计数变量别依赖循环自增**：`for (n=0;n<4;++n){ ... break; }` 走 `break` 时 `n` 不递增 →
   曾使 `parse_rect_clean` 把所有矩形判失败并静默置 0。
   对策：解析成功即 `seg[n++]`，另加 sanity 计数兜底。
2. **解码前必须 `s3_text_init()`**：漏了不报错，只把 Big5 原字节输出（数量全对、中文全乱码）。
   对策：probe 启动即 init，未 ready 直接退出。详见 `docs/UI布局与Menu.ini.md`。
3. **别为"过验证"改写数据**：TSV 里把制表符换成空格会让两侧都"对上"但值已被改写（同四.3）。
4. **`size_t` 下溢 → 堆越界读（段错误）**：`end - off - FRAME_HDR` 为负时被当成巨大无符号数，
   `span` 因此不被裁剪 → 越界读（`root=20000`/Statusbar 素材，M2 收口时修复）。
   对策：长度差先做**有符号判断**，不足即归零，绝不拿无符号减法当"可用量"。
5. **快速点按整次丢失**：按下/抬起落在同一帧时，用"电平判定抬起"（`prev_ldown`）会整次丢点击
   → 改「按下边沿记录 press + 无按压即触发」（`if (pt.lclick) press=hit;` / `if (!pt.ldown && press)`）。
6. **安卓 Back 键默认退出 Activity** → 需设 `SDL_HINT_ANDROID_TRAP_BACK_BUTTON=1` 拦下，
   再把 `SDLK_AC_BACK` 当"右键返回"用。
7. **`git add` 后 commit 前的 CRLF 警告是正常的**（Windows 换行），不是错误。
8. **装包 ≠ 生效**：`pm install -r` 不会重启已运行的进程，看到的仍是旧版 →
   每次装机后必须 `am force-stop` 再重开（2026-09-16 用户"没装上"的真相）。
9. **UI 状态变更只在"切换边沿"做，不要每帧无条件 set**：
   朝堂分支每帧 `set_visible(1)`，把命令阶段刚收起的菜单又顶了回来。
   对策：用 `last_court` 一类沿检测，进视图时才恢复默认状态。
10. **命令号必须按"当前场景上下文"解释**（2026-09-16 实测踩坑）：
    原版命令号是**场景内局部**语义 —— 存檔畫面的「確定/取消」= cmd 1/2 与主選單撞号
    （点取消又回存档画面），存档槽 cmd 11~20 与選擇時期剧本按钮 11~17 撞号（点槽位跳剧本）。
    对策：分发时先判 `roots[0]`（220=存档 / 100=選擇時期），再解释命令号。
11. **交互状态机必须在"视图/场景切换"时复位**（2026-09-17 实测踩坑，★ 容易漏）：
    长按（=右键）会**先产生一次 `lclick` 边沿**，紧接着 `rclick` 把视图切走；
    那次按压的"抬起"就永远不会被原分支处理 → 该分支的按压状态停在"按下中"。
    下次再回到该视图，第一帧便拿着**旧坐标**触发一次点击
    （实测：进「情報」命令阶段时凭空选中了"永安"，还弹出"需先調查"的提示 ——
      看着像功能坏了，其实是幽灵点击）。
    对策：把按压/拖动状态**提到文件作用域**，在视图切换的**边沿**统一清零
    （`g_map_*` 即为此改的）；凡"按下记状态、抬起才触发"的交互都照此办理。
12. **`input swipe x y x y 900` 之后，紧随的第一次点击可能被吞**：自动化脚本里
    长按与下一次点击之间留一拍，或对该次点击做重试。
13. **★ 玩家可见文案的权威源是 `Setting\Text.ini` 的 `String` 表，不是 `Menu.ini` 的 `Comment`**
    （2026-09-17 用户指正 + 数据复核）：`Menu.ini` 的 `Comment` 只是**开发者注释、可能过期** ——
    剧本按钮 105 的 Comment 写「臥龍出淵」，而实际显示名是 `Text.ini` 的 `String 404 = 赤壁之戰`
    （全库检索「臥龍/卧龙」**0 处**；按钮的可见文字是烘焙位图 `\MM\Button\Age05`，与注释无关）。
    对策：凡"玩家看到的文字"（剧本名、菜单项、提示语）一律先查 `Text.ini`；
    `Menu.ini` 的 Comment 只当作"布局用途"的辅助线索。
14. **同一份选择状态若有两个持有者，新增界面必须回写旧持有者**（2026-09-17 实测踩坑）：
    I2 大地图版（lord_picker）选中君主后没回写 `kingdom_scene` 的下标 →
    进战略层时 `my_lord = s3_kingdom_selected(kd)` 取到空 → **全城「我方 0」**
    （我方金框、我方全軍名册全失效，观感等同"名册为空"复发）。
    对策：新增 `s3_kingdom_select()` 并在新界面点击时同步；凡是"下游靠某个 getter 取当前选中"
    的地方，加第二入口时都要检查是否需要回写。
15. **判断"某数据是否存在"要先穷举字段再下结论**（2026-09-17）：
    我据 `General02.ini` 只有 `Name + City1..7`（无登场年份）就差点认定"武将登场无数据" ——
    实际上**登场是事件驱动**：`Setting\Event.ini`（36 事件 / 184~225 年）里的
    `16 太史慈 196/11`、`24 徐庶推薦諸葛亮 207/10`、`25~27 三顧茅廬` 就是武将登场。
    对策：下"数据不存在"的结论前，先列全 `Setting\*.ini` 的字段/文件名扫一遍（尤其是 `Event*.ini`）。
16. **读本地 docx（第三方资料）的两条**：① 结构用 `doc_resolve_document_structure`（分页 limit=150）；
    ② **表格单元格的 `text_preview` 会被截断**，必须按 `table_id` 逐张调 `doc_get_table_info` 才有完整内容。
17. **不要据"开局快照"推断长期上限**：统计"某剧本登场武将数"时得到的是**开局值**，

### 四·补二 交互与呈现约定（2026-09-16 增补）

1. **平板电脑没有右键** → 所有"右键返回"必须同时支持**长按**：
   presenter 层已实现（按住 > 600ms 且位移 < 20 逻辑像素 → 触发一次 rclick 边沿；
   拖动不触发）。Android 返回键仍是同一通道（`SDLK_AC_BACK`）。
2. **呈现模式切换收敛到幂等函数** `apply_present(p, kind, cw, ch)`，禁止三处手工 set：

8. **模拟器自动点击的坐标标定（2026-09-17 实测，可直接复用）**：
   - **y 必须先加状态栏高度 48px**（2560×1440 / density 320）—— `input tap` 用的是屏幕坐标，
     而 presenter 算的是窗口坐标（窗口从状态栏下开始）。旧笔记记的 "~72px 偏差" 是
     另一种 density 下的同一现象（24dp × density）。
   - **校准法**：先点一次并读 `ALOG("input: lclick=... at %.0f,%.0f")` —— 它回显 presenter
     反算出的逻辑坐标，与注入值一比即得偏移；**别靠截图目测**（截图是缩放过的，误差可达 20px）。
   - **每个场景的逻辑→设备映射不同**（视口/宽高比不同），实测：
     | 场景 | 映射（device_x, device_y） | 备注 |
     |---|---|---|
     | 主菜单（640×480 + EXTEND） | `(352 + lx*2.9, 48 + ly*2.9)` | content rect 352,0 1856×1392 |
     | 朝堂（640×480 + **STRETCH**） | `(lx*4.0, 48 + ly*2.9)` | 非等比！x×4.0 / y×2.9 |
     | 大地图 / 选择器（1024×556 + COVER） | `(lx*2.5036, 48 + ly*2.5036)` | 等比 2.5036 |
   - **控件矩形取法**：静态 UI 查 `.workbuddy/data/json/ui.json`（子窗口 `Range` **相对父窗口**）；
     自绘界面（kingdom/editor/admin/gen_picker）查源码常量。经验值：
     行政菜单按钮 `y = 36 + 33g`（朝堂 zoom 1）、**子选单固定从菜单顶部展开**
     （`y = 36`，与所属组无关），项中心 `≈ 36 + 14 + 26i + 13`；
     选择器行 `y = 126 + 44i`（画布 1024×556 下的设备换算前）。
   - **长按**：`input swipe x y x y 900`（同点 900ms）→ presenter 判定为右键；
     注意 `input swipe` 的时长参数是**毫秒**。
   - 命中判定是**左闭右开**（`y >= r.y && y < r.y + h`）→ 落在项下边界会 miss，
     点击一律取**项中心**，别贴边。

### ⛔ 本机 Git 操作红线（2026-09-14 实测踩坑）

- **禁止执行 `git gc` 和 `git filter-repo`**。二者都会**摧毁 `.git`**：报
  `fatal: not a git repository (or any of the parent directories): .git`，
  停手后 `.git` 只剩 `info/` 与 `objects/`，`HEAD`/`config`/`refs`/`index`/`hooks` 全丢。
  （`filter-repo` 收尾固定调用 `git gc --prune=now`，因此也一样不可用。）
- 需要改写历史 → 用**手工重建**：
  `read-tree` → `rm --cached` → `write-tree` → `commit-tree`（`GIT_*_NAME/EMAIL/DATE` 还原作者与时间）
  → `update-ref` → `reset --hard`。完整脚本见 `memory/2026-09-14.md`「收尾：仓库历史净化」。
- `git reflog expire --expire=now --all` **安全**，但**不要接 `gc`**。
- **不做 gc 也能让远端干净**：`git push` 只传**可达对象**；只要 refs 不指向旧提交，
  远端就不会包含被移除的文件。用 `git rev-list --objects --all | grep <路径>` 验证。
- **改历史前必须全量备份到仓库目录之外**，并在**纯 ASCII 路径副本**上操作（中文路径会叠加额外坑）。
