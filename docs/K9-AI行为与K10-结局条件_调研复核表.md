## 一、K10 结局与胜利条件（原版口径比预想的清楚）

| # | 项目 | 原版行为 | 我方现状 | 差异 | 我方拟定方案 | **你的决定** |
|---|---|---|---|---|---|---|
| A1 | **统一判定** | 消灭**所有其他势力**即算统一 —— **不必占领全部城池**；若野外还有敌方残军（未归城）则不算，会有军师提醒【攻略】 | 无判定 | 新 | 判定 = 地图上不存在"非我方且非在野且有人/有城的势力" | |
| A2 | **时间上限** | **公元 280 年**强制结束："司马炎统一全国，天下归晋"，未统一即游戏结束【攻略】 | 剧本 1 起于 184 年；月份在跑，无上限 | 新 | 采用 **280 年硬上限**（184→280 = 96 年，对我们 32.6 年级成长曲线很宽松） | |
| A3 | **结局分支** | **两种**：**天下大乱**（篡位，几年后天下重新混乱）/ **天下大治**（汉帝主动让位、天下太平）【攻略，多来源一致】 | 无 | 新 | 实现两分支 + 一张结局文本/画面（简版：文字结局 + 势力统计） | |
| A4 | **好结局（天下大治）条件** | ① 城池**平均开发度 ≥ 300**（另一来源说 ≥500）② 武将**平均忠诚 ≥ 70** ③ 武将**平均等级 ≥ 10** ④ 我方**历史武将总数 ≥ 150**（**不含自设武将与俘虏**）【攻略】 | 无 | 新 | 四项**全达标 → 大治**，否则大乱。<br>⚠ 与我们的改造有交互：等级上限改 50、武将 421 人 vs 每剧本只登场一部分 → **"武将 ≥150"在剧本 1 可能要 + 相性/招降才能凑到**，需实测 | |
| A5 | 结局演出深度 | 原版有结算演出【攻略】 | 无 | 新 | 首版只做**文本结局 + 数据摘要**（年份/城数/武将数/灭势力数），画面后续补 | |
| A6 | **势力灭亡处理** | 被灭势力的**全部武将（含君主）在最后被灭的城市转为在野**；君主被俘时**没有"俘虏"选项，只能释放或斩首**【甲 §19.3 + 攻略，两来源一致】 | 无 | 新 | 采纳（与 Q4 野将机制同一套） | |
| A7 | 玩家自身败北 | 我方城全失 / 君主被俘即失败【推断】 | 无 | 新 | `我方城数 == 0` → 败北结局 | |
| A8 | 隐藏剧本解锁 | 通关任一剧本 → 解锁"**天下归魏**"（230 年，敌曹操 7 级、我方新君 1 级）【甲 §16.1 + 攻略一致】 | 選擇時期已有 7 个入口，**无解锁逻辑** | 新 | 存档记录"已通关"，解锁第 7 剧本 | |

## 二、K9 AI 势力行为

| # | 项目 | 原版行为 | 我方现状 | 差异 | 我方拟定方案 | **你的决定** |
|---|---|---|---|---|---|---|
| B1 | **AI 自动升级** | 电脑武将**即使不打仗也随时自动升级**；而**我方原本不自动**（要靠战斗）—— 玩家抱怨"跟不上电脑等级"【攻略，多来源一致】 | 需求① 已改成**我方也自动升级**（C9），AI 同规则 | 已定 | **已在 M 区定稿**（AI 用普通难度档）；此条仅确认，**不需要改** | |
| B2 | AI 月度行为 | AI 会**开发 / 征兵 / 搜索 / 调兵 / 出兵**；被玩家普遍评价"**AI 很低，多数时候来回移动**"【攻略】 | 无（AI 完全不行动，回合跳过后不动） | 新 | 首版做**最小 AI（MVP）**：每回合按优先级 ①紧急征兵/补兵 ②开发（缺钱）③搜索（有野将且相性近）④**出兵**（见 B3） | |
| B3 | **AI 出兵倾向** | 倾向攻击**相邻的、兵力弱于自己**的城；**君主威望低的一方更常被攻击**【甲 §L1① + §23.3】 | 无 | 新 | 出兵评分：`兵力比 × 邻接数 − 目标守军 × 威望系数`；威望低 → 被攻击概率高（与 L1① 一致） | |
| B4 | AI 外交 | 原版有同盟/解盟；**威望低时更易被围攻**【甲 §23】 | 无 | 新 | 首版：AI 间**按友好度随机**结盟/解盟；**暂不做"反玩家联盟"**（该说法来自不可信来源） | |
| B5 | AI 搜野将 | 电脑占领空城后**自动搜走相性接近的在野武将**【甲 §19.3④】 | 无 | 新 | 采纳（放在 B2 的搜索分支） | |
| B6 | 难度对 AI 的影响 | **简单**：敌方升级慢、后期**不会**自动学必杀技；**普通**：标准；**困难**：敌方升级快、**后期自动学会必杀技**；"不改变核心数值体系"【甲 §21.2】 | G3 有"难度"设置项但无实现 | 新 | 采纳；我方月经验系数 **0.7 / 1.0 / 1.5**（困难=1.5，2026-09-17 用户定） | |
| B7 | AI 计算量与性能 | 原版纯 CPU，无性能顾虑 | 我们要跑在手机上，且已有 70 城 × 20 势力的规模 | 新 | AI **逐势力错峰结算**（每回合只算 1/4 势力，4 回合轮完），避免回合结束时卡顿 | |
| B8 | AI 与"守城支援"的交互 | **援军必须是"本月未执行过任何命令"的武将**【攻略】 → 侧面印证 A2「每将每月 1 条指令」是原版机制 | 我们 A2 已实现；A2 例外"城池被攻打时已行动者仍可支援"是**用户口径** | 差异 | 保留用户口径（我方守城可支援）；**AI 侧按原版：只有未行动的将能当援军** | |

## 三、与本项目改造的交叉影响（提醒）

| 项 | 影响 |
|---|---|
| **A4 好结局"武将 ≥150"** | 我们每剧本只登场部分武将 + 等级上限 50 → 需要靠招降/搜索凑人数；建议实测后再定阈值（可下调或改为"占该剧本武将总数的 X%"） |
| **A2 时间上限 280 年** | 与我们的**自动升级曲线**（32.6 年满级）不冲突；但**AI 也自动升级**，长局 AI 会很强 → 需在 B3 出兵评分里考虑 |
| **A6 君主不可俘虏** | 会影响将来"俘虏"系统的界面选项（君主只有 释放/斩首） |
| **B8 援军条件** | 与用户口径 A2 例外**不同**（用户允许已行动者守城支援）—— 已按用户口径实现，此处仅留档 |
