# 复测反馈修 Bug：子选单不收起（20:40~20:45）—— 已修 + 装机

## 用户反馈（附截图）
大地图版统计栏 **城數 6 · 關口數 6 复测没问题** ✅（T22/关口修复确认）。
新问题：**一级菜单未点选的情况下，子菜单仍是展开态** —— 截图里「軍政」蓝色高亮、
子菜单（徵兵/訓練/戰爭/整備/調兵）展开着，底部提示「已取消「徵兵」」。
即：**命令取消后回到朝堂，子选单没有收起、一级按钮还停在选中态**。

## 根因（`engine/src/admin_menu.c`）
`S3AdminMenu` 只有 `int open`（= 当前展开的组，-1 未展开）一个状态位。
`s3_admin_on_click()` 在**子选单项**分支里只派发 `on_cmd(...)`，**从不复位 `open`**
→ 命令进命令阶段（菜单被 `set_visible(0)` 收起）后，UI 侧的展开态一直留着；
用户长按取消 → `admin_cancel_pending()` 把菜单重新显示 → **旧展开态原样呈现**。
（渲染里 `state = (hover_btn==g) ? 2 : (open==g ? 1 : 0)`，所以「軍政」显示成展开态的高亮。）

## 修法（4 处调用 + 1 个新接口）
1. **主修**：子选单项命中后，派发完即 `m->open = -1; m->hover_item = -1;`
   （原版行为也是"选完即收"）。
2. 新增 `s3_admin_collapse(m)`（.c/.h），并把"**重新显示菜单**"的入口全部接上：
   - `admin_set_pending_x()`：进命令阶段收起菜单时 → 同时收起子选单
   - `admin_cancel_pending()`：取消命令回朝堂 → 强制收起
   - 新开局进朝堂 → 从"无展开"开始
   - 朝堂视图切换边沿（`last_court != court`）→ 收起
3. **顺带修一个手滑引入的错**：复位 `open` 后再用 `GROUPS[m->open].label` 拼"尚未實現"提示
   → 会显示错组（第 1 组）；改为**派发前先存 `const int g = m->open;`**。
